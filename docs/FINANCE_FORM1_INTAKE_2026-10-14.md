## Implemented scope

An authorized Budget package preparer can start the first whole package from
a current independently approved SPA source. The SPA detail links to intake.
Four original opening boundaries per entity require explicit actual, forecast
or missing treatment. Actual candidates retain their original owners, Fund,
entity, balance date/boundary and adoption or joint certification; preview and
retention check exact scope and currentness through the existing cash services.
The annual opening references the H1 January boundary, never a sum of stocks.

Forecast inputs provide visible original worksheet rows for cash in/out,
new restriction identities and restriction additions/removals. Each requires
original dated movements, coverage, basis and explicit zero declarations when
applicable. Uploaded worksheet bytes use the existing document validator.
Budgetary flow totals do not become cash movements. Links permit inspection
of the original cash certificates and restriction identities.

A normal multipart source-preview submission creates no provisional financial
record. A signed, one-hour preview binds the actor, original SPA and decisions,
whole source inventory and current package version. Final retention recaptures
sources and requires the same original worksheet bytes; clerks reattach files
after preview or validation errors. There is no new attachment cache, server
draft store, ledger rule, permission, model or migration.

The PhilHealth editor shows original signed receipt, restriction and expenditure
components, explicit splits, treatment / counterpart choices and whole-source
coverage. Treatment starts unresolved; coverage starts missing. A changed
source inventory resets hidden treatment partitions rather than inheriting
unrelated selections. Hidden structured inputs are generated by the editor;
clerks do not construct JSON. Existing exact-partition / sign / overlap-capacity
and unknown-control validators remain authoritative.

Final submission delegates to existing PhilHealth preparation, assembly capture
and immutable whole-package retention. It preserves source bytes and version
history and requires the existing independent office review route. There are
no statutory signing, issuance, spending or actual cash authority flags supplied
by this screen. UAT membership denies mutation, including mixed operational
grants. Current source visibility is required independently of package permission.
