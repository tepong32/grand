## Reproduction and change

For the existing configured payment-release reporting basis, the report converted
the retained first release timestamp directly to a UTC calendar date. A regression
test reproduced a local March 1, 00:30 release appearing on February 28 instead.
Baseline: one expected failure, 1.067s, exit 1; `.tmp/tax-release-date-baseline.log`.

Reuse the local activity-date conversion validated for the Treasury register.
This changes only the calendar date projected from the retained release instant.
The rule's selected reporting basis, earliest-release selection, tax base, rate,
withholding amount, source checksums and posted history are unchanged. Reversals
continue to use their own journal entry date. Missing releases stay pending and
are not replaced with voucher, issue, bank-acknowledgement or posting dates.

This implements the existing configured behavior; it does not prescribe statutory
tax timing or confirm local applicability of a tax rule. Synthetic configuration
and retained source fixtures are expressly not actual bank or LGU acceptance.
Partial-payment attribution and rule applicability are unchanged by this fix.
